SKILL2EARN — QUICK START FOR PRESENTATION

CORE DEMO ONLY
1. Student signs up/logs in.
2. Student browses open jobs and applies.
3. Employer signs up/logs in.
4. Employer posts a job and views applications.
5. Employer changes an application status (if the current UI has the status action available).

DATABASE SETUP
1. Open Supabase Dashboard for the project configured in js/supabase-client.js.
2. Go to SQL Editor > New query.
3. Open SUPABASE_QUICK_SETUP.sql, copy the entire file into the SQL editor, and Run.
4. In Authentication > URL Configuration, set Site URL to your local development URL if needed. For Live Server this is commonly http://127.0.0.1:5500 or http://localhost:5500.
5. In Authentication > Providers > Email, for the presentation you may temporarily turn OFF email confirmation so demo accounts can sign in immediately. Turn it back on for a real deployment.
6. Open the SKILL2EARN folder in VS Code and use Live Server to open index.html. Do not open the HTML files with file://.

IMPORTANT
- The current Supabase Project URL and publishable key are in js/supabase-client.js. Verify they belong to the intended project. Publishable/anon keys are intended for browser use; never put a service_role/secret key in the frontend.
- Run the SQL on a fresh/empty demo database when possible. If the database already has tables with different column types or structures, do not blindly reset it; inspect Table Editor first.
- Student email validation currently allows @tip.edu.ph and @edu.ph.
- If signup succeeds but login says profile missing, confirm the SQL trigger on_auth_user_created_skill2earn exists and the signup created a row in public.profiles.
- If the page reports an RLS/policy error, check that the complete SQL file ran successfully and that the user role in public.profiles matches the login page used.
- Do not present removed pages (admin, verification, resume builder, support, settings, reports) as required for the core demo. They remain in the project folder but are outside tomorrow's main workflow.
